# Methodology

## Core principles

1. Understand before modifying.
2. Repository evidence beats generic templates.
3. Preserve useful existing structure.
4. Route context instead of stuffing context.
5. One canonical home per fact.
6. Separate stable knowledge from active work.
7. Progressive disclosure over always-on payloads.
8. Explicit contracts where recurring workflows benefit.
9. Minimalism and maintainability over file proliferation.

## Maturity-aware behavior

### Sparse/greenfield

- establish minimal orientation and canonical homes
- avoid speculative hierarchy

### Early

- standardize canonical sources before duplication grows
- create scoped instructions where patterns are real

### Established/monorepo

- preserve conventions and minimize path churn
- fix routing/conflict/duplication before introducing abstractions

## Context budget posture

- keep root routing concise
- keep always-on instructions limited to universal rules
- keep details in references loaded only when relevant

## Drift handling

When docs and implementation disagree:

1. identify evidence source
2. mark ambiguity explicitly if intent is unclear
3. fix safe documentation drift where evidence is clear
4. avoid inventing requirements
